# Конвенция по написанию кода

## Стилистика кода

- Убирать ненужные точки с запятой в конце;
- Везде писать одинарные кавычки `''`, двойные нужны в случае, если в строке есть одинарные, например `"I'm happy to code"`;
- Для импорта файлов c расширением `.svelte.js` в конце обязательно явно указывать расширение `import { addTask } from './state.svelte.js'`, чтобы не перепутать с файлами компонентов `.svelte`;
- Использовать implicit return в стрелочных функциях:
  ```
  const getTasks = () => return tasks - НЕТ
  const getTasks = () => tasks - ДА
  ```
- Если в теле стрелочной функции всего одно выражение, то его надо писать вместе с объявлением функции в одну строку и без фигурных скобок:
  ```
  const logError = () => {
    console.log('ERROR')
  } - НЕТ
  const logError = () => console.log('ERROR') - ДА
  ```
- Не писать функции ради функций, например нет смысла в отдельной функции `const add = () => count += 1`, если можно написать `count++`, где оно используется;
- Обрамлять все операторы пробелами:

  ```
  const a=b+c - НЕТ
  const a = b + c - ДА
  ```

  То же самое относится и к пропам:

  ```
  let {done=$derived(), title}=$props() - НЕТ
  let { done = $derived(), title } = $props() - ДА
  ```

- В основном, если для объяснения кода требуется писать комментарии, то код непонятный и требует рефакторинга. Исключение составляют случаи, когда код не может быть полностью самостостаточен, например, когда в нем используется сложная математическая формула для расчета. В таком случае, в комментарии необходимо пояснить происходящеее или оставить ссылку на описание принципа расчетов.
- Если уровень вложенности больше 2 - необходим рефакторинг ([пример на С++](https://www.youtube.com/watch?v=CFRhGnuXG-4), смотреть идею рефакторинга, а не стилистику кода);
- Наименование булевых переменных лучше начинать с is (`isOddNumber`, `isNodeModule` и т.д.), если переменная отвечает на вопрос «является ли что-то истинным» и does (`doesItWork` и т.д.), если вопрос «делает ли какая-то сущность что-то»;
- Наименование функции должно отвечать на вопрос что делает функция, например `addNumber`, `calculateTax`, `displayError`, `formatDate` и т.д.;
- Стиль именования:
  - PascalCase - классы;
  - camelCase - переменные, функции;
  - SCREAMING_SNAKE_CASE - константы.
- При наименовании переменных необходимо соблюдать последовательность, например, если есть задача со свойством `isDone`, то для получения невыполненных задач необходимо назвать переменную `undoneTasks`, а не `unfinishedTasks`;
- Не использовать сокращенные названия переменных, т.к. сокращения не всегда понятны `res` это `result` или `response`?
- Для удобства лучше использовать деструктуризацию:

  ```
  {#each tasks as {title, done}}
    <p>{title}</p>
    <input type="checkbox" checked={done} />
  {\each}
  ```

  ```
  let { data } = $props()
  let { tasks } = $derived(data.tasks)
  ```

- Избегать дублирования атрибутов элементов и свойств объектов типа `src={src}` и `title: title`; вместо этого писать `{src}` и `title`;
- Блоки `(#each`, `#if` и т.д.) индентируются:

  ```
  <div>
    {#each tasks as task}
      <p>{task}</p>
    {/each}
  </div>
  ```

- Если единичное условие if, то нет смысла писать с фигурными скобками в несколько строк `if (statement) return 1`;
- Если 2 return и появляется дополнительный уровень вложенности из-за `if`, то решение либо тернарный оператор, либо охранное выражение.

## Пример оформления индентаций

```
function stop() {
  if (!interval) return
  clearInterval(interval)
  interval = null
}
```

1. Открывающая скобка функции на строке объявления функции через пробел после обычной строки;
2. Индентация кода внутри функции на 1 уровень (2 пробела, см. настройка проекта) от начала строки объявления;
3. Пробел после if;
4. Пробелы вокруг оператора присваивания (=).

## Стили

- Для задания стилей использовать классы, не теги;
- Наименование классов в соответствии с [БЭМ](https://bem.info/ru/methodology/quick-start/);
- Все свойства пишутся в алфавитном порядке, это нужно для быстрой ориентации в коде:

  ```
  .block {
    align-items: center;
    background-color: red;
    color: green;
    display: flex;
    font-size: 12px;
  }
  ```

- Размеры единиц только пиксели;
- Не использовать !important, это нарушает специфичность;
- Для задания цвета фона лучше писать свойство `background-color`, а не `background`;
- На интерактивные элементы (кнопки, чекбоксы и т.д.) для лучшего UX надо добавлять свойство `cursor: pointer`;
- Не использовать код из dev режима в фигме, за исключением сложных градиентов.
