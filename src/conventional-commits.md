# Конвенция Conventional Commits

Документ описывает формат сообщений коммитов на наших проектах по спецификации [Conventional Commits](https://www.conventionalcommits.org/).

## Структура сообщения коммита

```
тип(опционально – область): краткое описание

[тело]

[футер]
```

Пример: `feat(auth): добавить вход через Google`

## Типы

- **feat** — новая функциональность (→ MINOR в SemVer)
- **fix** — исправление бага (→ PATCH)
- **docs** — документация
- **refactor** — рефакторинг без смены поведения
- **test** — тесты
- **chore** — рутина (зависимости, конфиги)
- **build** / **ci** — сборка и CI

## Ломающие изменения

Несовместимое изменение (→ MAJOR в SemVer) помечается одним из способов:

- восклицательный знак после типа: `feat!: ...`
- футер: `BREAKING CHANGE: описание`

## Правила на проектах

- Описание, тело и футер всех коммитов пишутся на русском языке.
- Описание короткое, в повелительном наклонении («добавить», а не «добавлено»).
- Область (`auth`, `api`, `ui`) указывается по возможности, но необязательна.
- Ссылка на задачу — в футере или описании: `fixes #42`.
- Формат машиночитаемый: по нему автоматически генерируются changelog и версии SemVer (инструменты вроде semantic-release).
